# Язык программирование С++
Язык программирование С++ представляет высокоуровневый компилированный язык программирование общего назначения со статической типизацией
 Своими корнями он уходит в язык СИ который бвл разработан 1969-1973 годах в компании Bell Labs программистом Деннис Ритчи  
 В начале 1980 годов Датский программист Бьерн Страуструп работал в компании Bell Labs, разработал С++ как расширение к языку СИ  
 Фактически в начале С++ просто дополнял язык СИ с некоторыми возможностями ООП  
 В начале язык назывался СИС классами  
 С++ является компилированным языком, а это значит, что компилятор транслирует исходный код на С++ в исполняемый файл, который содержит набор машинных инструкций

# Зачем нужно компилировать исходные файлы  
Исходный С++ файл - это всего лишь код, но его не возможно запустить как программу и использовать как библиотеку, поэтому каждый исходный файл требуется скомпилировать в исполняемый  

Этапы компиляции  
1. Препроцессинг- это макро процессор который преобразует программу для дальнейшего компилирование, на данной стадии происходит работа препроцессорными делективами  
например: препроцессор добавляет хэдеры в код (#include), убирает комментарии  
2. Компиляция - это происходит преобразование в асемблерный код. Это промежуточный этап между высокоуровневым языком и машинным кодом  
3. Ассемблирование - перевод ассемблерного кода в машинный  
   Объектный файл - это созданный ассемблерным промежуточный файл, хранящий кусок машинного кода. Этот кусок машинного кода, который еще не был связан с другими кусками машинного кода, называется ОБЪЕКТНЫМ КОДОМ  
4. Компоновка - Компоновщик(Линкер) связывает все объектные файлы и статические библиотеки в единый исполняемы файл который мы можем запустить
5. Загрузка

Файлы проекта  
1. vcxproj (основной файл проекта). Это XML-файл, в котором хранятся все настройки проекта: какие исходные файлы включаются в сборку, какие компилятор и компоновщик использовать, какие макросы определены, пути к библиотекам и многое другое. Именно он связывает все компоненты в единое целое и задаёт правила сборки  
2. .vcxitems. Этот файл не создаёт отдельный исполняемый файл. Он служит для того, чтобы один проект мог ссылаться на другой (например, общий модуль или библиотеку) и включать его файлы в процесс сборки ссылающегося проекта  
3. .sdf. Это файл базы данных просмотра. Он создаётся на основе анализа заголовочных файлов и нужен для функций IntelliSense
4. .suo. Файл параметров пользователя. Он сохраняет настройки конкретного пользователя (например, темы оформления, цветовые схемы), чтобы при следующем открытии проекта среда вела себя так же, как в прошлый раз
5. CMakeLists.txt. Если вы используете систему сборки CMake, этот файл задаёт правила генерации проекта. Visual Studio умеет работать с такими проектами: она может открыть папку с CMakeLists.txt и настроить всё для сборки


Папки в проекте  
В Обозревателе решений файлы сгруппированы по логическим папкам:  
1. Source Files — здесь лежат файлы с исходным кодом (.cpp, иногда .c). В одном из таких файлов обычно располагается точка входа — функция main() (для консольных приложений) или WinMain() (для Win32)
2. Header Files — в этой папке хранятся заголовочные файлы (.h для C, .hpp для C++). Они содержат объявления: прототипы функций, описания классов, констант, общих типов данных. Важно: заголовочный файл подключается в исходные файлы через директиву #include, но сам по себе не компилируется — он просто вставляется в код как текст
3. Resource Files — сюда помещаются файлы ресурсов: изображения (.bmp, .jpg), иконки (.ico), курсоры (.cur), строки для локализованных текстов и т.п
4. External Dependencies — эта папка отображает файлы, которые используются в коде, но не входят в состав проекта (например, сторонние библиотеки, на которые есть ссылка)
